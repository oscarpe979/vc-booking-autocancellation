# 09: Lightweight Admin Dashboard & Configuration UI

**What to build:** An enterprise IT administrator can open a lightweight, server-rendered web dashboard (`GET /admin`) on the service host (127.0.0.1, shared password) with a clean, Google-style interface to monitor the fleet in real time, enroll rooms, and configure autocancellation behaviors and exemptions. The dashboard provides an instant 1-click emergency kill switch, a tripwire reset, a search bar to filter rooms, a live status table, an enrollment view, a promotion readiness report, and a configuration panel to view and update settings, including meeting duration thresholds, VIP organizer email lists, title keyword exemptions, timeout durations, and per-room operational modes (Disabled, Monitor Only, Dry Run, Live), without modifying code or restarting the service. Every change is validated, persisted through `IFleetConfigStore`, and audited before it is applied.

**Blocked by:** 01: Core Scaffolding & End-to-End Tracer Bullet, 05: Startup Quarantine, Booking Policy & Lifecycle Guards, 10: Corporate SMTP Email Notification Engine & Template System, 11: Fleet Roster, Room Enrollment & Durable Configuration Store

**Status:** ready-for-agent

- [ ] Embedded Fastify web route (GET /admin) renders a clean, minimalist Google-style HTML dashboard with sub-50ms page load times and zero client framework build dependencies
- [ ] The dashboard binds to 127.0.0.1 only. It requires the shared `ADMIN_DASHBOARD_PASSWORD` (constant-time compare, rate-limited logins, HTTP-only `SameSite=Strict` session cookie, and a CSRF token on every state-changing request), and refuses to start when no password is configured. Audit actor is `admin`
- [ ] Prominent 1-click Emergency Kill Switch toggle that halts or resumes automation across the fleet without restarting the process (fleet-gate effects in ticket 11, LLD §5.8). Activation applies in memory immediately even if persisting fails, is shown as `active (not persisted)`, and is retried until persisted; deactivation requires a successful persist. The dashboard shows when `AUTOCANCEL_KILL_SWITCH` holds the switch active (the parameter is re-read every 30 seconds)
- [ ] A tripped tripwire is shown with its `tripwireTrippedAt` time, and an admin can reset it; the reset is persisted and audited
- [ ] Real-time search bar that filters the room fleet by room name, room ID, organizer email, or lifecycle status
- [ ] Fleet table displays each room's mode, current meeting subject, organizer, presence state (Occupied / Empty / Unknown), workflow phase (Idle, Quarantined, ActiveMeeting, CountdownScheduled, PromptPending, PromptVisible, ValidatingJIT, Released), block reason, and remaining countdown seconds
- [ ] Configuration and exemption panel allows administrators to view and update `FleetSettings`:
  - Empty-room timeout (EMPTY_ROOM_TIMEOUT_MS), warning duration (PRE_TIMEOUT_WARNING_MS), and grace period (POST_TIMEOUT_GRACE_PERIOD_MS)
  - Long-meeting exemption threshold (LONG_MEETING_EXEMPTION_THRESHOLD_MS)
  - Native CheckIn window (NATIVE_CHECK_IN_WINDOW_MINUTES), ultrasound sensor toggle, automatic check-in delay, booking sync coalesce delay, and readiness recovery delays
  - Early Departure release toggle (EARLY_DEPARTURE_RELEASE_ENABLED, default off)
  - VIP / organizer exemption list (EXEMPT_ORGANIZERS) and meeting title keyword exemptions (EXEMPT_TITLE_KEYWORDS)
  - Corporate SMTP relay settings: host (SMTP_HOST, e.g. outlook.suncorp.com.au), port (SMTP_PORT, e.g. 25), sender address (SMTP_FROM), TLS toggle (SMTP_SECURE), and global notifications toggle (NOTIFICATIONS_ENABLED); no SMTP credentials are stored (secrets stay in SSM)
  - Per-room mode changes (DISABLED, MONITOR_ONLY, DRY_RUN, LIVE) restricted to the promotion path and transition rules in LLD §5.7. Promotion into DRY_RUN or LIVE, and LIVE → DRY_RUN, quarantines an in-progress meeting; demotion cancels workflows and restores the recorded native CheckIn baseline
- [ ] Every settings write is validated before it is persisted (LLD §5.10): `preTimeoutWarningMs <= emptyRoomTimeoutMs` and every timing is a positive finite number; the long-meeting threshold is finite and `>= 0` (`0` disables it); `nativeCheckInWindowMinutes` is one of 5, 10, 15, 20, 30, 60 and, in milliseconds, exceeds the `LIVE` release horizon; recovery delays are finite and non-negative; SMTP port is 1–65535 and `from` is a valid address. Invalid values are rejected with a message and never stored
- [ ] Enrollment view lists Discovered (not enrolled) workspaces and rooms flagged Missing, DeviceMismatch, AmbiguousWorkspace, CleanupIncomplete, or PresenceTelemetryUnavailable; the admin selects the managed device for an ambiguous workspace
- [ ] DRY_RUN → LIVE shows the readiness report (LLD §8.6), including a fresh read showing a controller is present (a connected `TouchPanel` with `Role = Controller`, `RoomScheduler` excluded, or a Desk Pro OSD) and a readable `SystemUnit.Uptime`, and requires explicit confirmation, which is audited with the report; no minimum dry-run duration is enforced
- [ ] Every dashboard change is persisted through `IFleetConfigStore` before it takes effect and is audited; a version conflict is shown as "changed by someone else; reload"; during a store outage, writes are rejected except kill-switch activation
- [ ] While the store has not loaded at startup, the dashboard shows **Configuration store unavailable: automation halted**
- [ ] Rooms in MONITOR_ONLY show utilization telemetry only, and are flagged `PresenceTelemetryUnavailable` when presence data is missing; the dashboard never writes sensor configuration as a side effect of viewing or monitoring
- [ ] Settings changes take effect immediately without a restart, but apply only to workflows started after the change; running countdowns and fixed warning deadlines keep the values they started with
- [ ] Automated tests verify dashboard HTML rendering, kill-switch activation and deactivation (including `active (not persisted)`), tripwire reset, settings validation, SMTP setting updates, mode-transition rules, and that every change is persisted via `IFleetConfigStore` and audited before it is applied
