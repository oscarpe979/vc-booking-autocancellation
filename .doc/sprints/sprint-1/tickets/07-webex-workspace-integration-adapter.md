# 07: Webex Workspace Integration Driver Adapter

**What to build:** An engineer can bind the domain engine to real Cisco collaboration devices using Webex Workspace Integrations. The adapter fulfills the Hexagonal contracts defined in ticket 01 (`IRoomPresenceDriver`, `IRoomInteractionDriver`, `ICalendarDriver`, `IDeviceConfigDriver`, and `IFleetInventoryDriver`) via the official Webex SDK, translating xStatus queries, xCommands, xConfigs, and xEvents to and from domain representations, enforcing device baseline configurations, serializing native check-in writes, and enforcing the outbound roster and command gate (LLD §7.1) on every command and configuration write. It respects the Webex platform constraints in LLD §9.

**Blocked by:** 01: Core Scaffolding & End-to-End Tracer Bullet

**Status:** ready-for-agent

- [ ] Webex integration initializes and manages machine account access tokens using OAuth credentials and activation tokens
- [ ] Presence queries and change notifications map accurately to and from `RoomAnalytics.RoomInUse`; a read failure resolves to `Unknown`
- [ ] Calendar availability maps to and from `Bookings.Availability.Status`/`TimeStamp` and `Bookings.Current.Id` (`Free`, `FreeUntil` with the next booking start, `BookedUntil`); a failed read returns `null`, never `Free`
- [ ] `getBookingDetails` maps to `Bookings.Get({ Id })` and `getCurrentBooking` to `Bookings.List({ ScheduleType: 'Current', Limit: 1 })`; a missing or unparseable organizer email maps to `null`
- [ ] `checkIn` maps to xCommand `Bookings.CheckIn` and returns a `CheckInResult`: success is `CheckedIn`; an error whose text contains `already checked in` (case-insensitive substring; macro text `Cannot check in booking that is already checked in.`, exact SSH and cloud text pending device test DT2) is `AlreadyCheckedIn`; anything else is `Failed`. `checkOut` maps to xCommand `Bookings.CheckOut` and rejects on failure; the adapter never calls `Delete`
- [ ] `Bookings.CheckIn` and `Bookings.CheckOut` are never retried automatically after a timeout, a network error, or any error response, because the command may have run on the device. The only retry is a `429` received before the command was dispatched to the device, within the workflow deadline
- [ ] *Pending device test DT1:* `getCheckInState` reads the booking's CheckIn state from whichever source DT1 identifies (`Bookings.Get`, `Bookings.List`, or an xStatus), maps it to `CheckedIn` or `NotCheckedIn`, and returns `null` when unreadable. It is a read with no side effects. If DT1 is negative, the method and `BookingCheckInState` are removed
- [ ] `Bookings.CheckOut` only works while `Bookings.CheckIn.Enabled = True` (LLD §5.6, §9); the adapter never toggles that setting to force a CheckOut
- [ ] `readPromptSurfaces` reads `Peripherals.ConnectedDevice` and `SystemUnit.ProductPlatform` with `status.get` when the coordinator calls it (LLD §5.11): `controllerIds` holds the sorted IDs of entries with `Status = Connected`, `Type = TouchPanel`, and `Role = Controller`; `RoomScheduler` panels are never included; `interactiveOsd` is true only for a verified interactive OSD (Desk Pro). It never rejects: a failed read or a `403` sets `inventoryReadable = false`. The adapter registers no topology listener and runs no polling timer
- [ ] `displayPrompt`, `restoreDismissedPrompt(roomId, target, prompt)`, and `clearPrompts(roomId, kind)` map to xCommand `UserInterface.Message.Prompt.Display` and `UserInterface.Message.Prompt.Clear` per target and feedback ID. `displayPrompt` always sends `Target=Controller` (plus the OSD per the platform rules) whatever the surfaces show, and returns `controllerCommandAccepted`, `displayedOnOsd`, and `osdActionable`; it never decides controller ownership (the coordinator does, ticket 03)
- [ ] `playAudioAlert` maps to one `Audio.Volume.Set(70)` plus `Audio.Sound.Play(Announcement, Loop Off)` (returns `false` on failure); `restoreAudioVolume` maps to `Audio.Volume.SetToDefault`
- [ ] xEvents `UserInterface.Message.Prompt.Response` and `UserInterface.Message.Prompt.Cleared` are parsed and dispatched to `onPromptResponse` and `onPromptCleared`; `OptionId` is normalized with `String()` and `Origin` is mapped to `PromptResponseEvent.origin`. There is no `Bookings.CheckedIn` subscription (it is not delivered to Workspace Integrations). The optional `BootEvent` subscription is parsed into `DeviceBootEvent` (`Restart`, `Shutdown`, `Upgrade`, otherwise `Unknown`) and dispatched to `onBootEvent`; it fires before the restart and is an early trigger only. Optional `Bookings.Start`/`End`/`Deleted` events may enrich `[EXTERNAL_RELEASE_OBSERVED]` logs only
- [ ] `getCodecTime` reads `Time.SystemTime` with its offset (`null` when unavailable); `getUptimeSeconds` reads `SystemUnit.Uptime` with `status.get` (`null` when unreadable or `403`); `getNativeCheckInEnabled` and `getNativeCheckInWindow` read `Bookings.CheckIn.Enabled` and `Bookings.CheckIn.WindowDuration` (`null` when unreadable)
- [ ] `enforceBaselinePresenceConfig(roomId, ultrasoundEnabled)` writes the presence baseline of LLD §5.12 (`RoomAnalytics.PeoplePresenceDetector`, `PeoplePresence.Input.HeadDetector`, `PeopleCountOutOfCall`, `PeoplePresence.Input.Ultrasound`, `RoomInUse.InCall`, `RoomInUse.LocalUsage`) as one `xapi.config.setMany` batch where possible, falling back to `xapi.config.set`, serialized per device (requires the `spark-admin:devices_read` and `spark-admin:devices_write` scopes; configs are not listed under `xapiAccess`); it returns `false` when any setting fails
- [ ] `enforceNativeCheckInWindow` writes `Bookings.CheckIn.WindowDuration` from `NATIVE_CHECK_IN_WINDOW_MINUTES` (default 60; RoomOS accepts only 5, 10, 15, 20, 30, 60), so native room no-show timers cannot race ahead of service release
- [ ] `setNativeCheckInEnabled` writes `Bookings.CheckIn.Enabled` through a per-device FIFO serialization queue (LLD §5.4): each write returns its own result, a failure is never swallowed, and a write made stale by a lifecycle change returns `false`. The value written is decided by the domain (ticket 05, LLD §5.6)
- [ ] `IFleetInventoryDriver.listDevices()` uses only the Control Hub device list (`devices.getDevices()`), never a device xAPI call, and returns every device in the org; `connectionStatus` maps `connected` and `connected_with_issues` to `connected`, `disconnected` to `disconnected`, and anything else to `unknown`; `isBookingCapable` is `false` for `RoomScheduler` Navigators and accessories
- [ ] Every xCommand and xConfig write passes the outbound gate (LLD §7.1): writes to devices the roster gate does not allow are rejected, as are writes to `MONITOR_ONLY` devices except mode-transition clean-up, and `Bookings.CheckIn`/`Bookings.CheckOut` commands and `Bookings.CheckIn.Enabled` writes are rejected for every device while the kill switch or tripwire is active (presence baseline and `Bookings.CheckIn.WindowDuration` writes are still allowed). The gate is injected (supplied by ticket 11; stubbed in this ticket's tests). Configuration writes are gated too, because location-limited activation does not restrict them
- [ ] HTTP `429` responses are retried by the adapter with jittered backoff honoring `Retry-After` (the SDK does not retry them), queued per device; a command that cannot be sent before its workflow deadline fails closed. A `403` outside the activated locations is reported as a failure (for status reads: `null`, `Unknown`, or `inventoryReadable = false`, never a healthy value)
- [ ] The integration manifest grants every xCommand and xStatus the adapter uses, including `Audio.Volume.Set`, `Audio.Volume.SetToDefault`, `Audio.Sound.Play`, `Bookings.Get`, `Bookings.List`, `Time.SystemTime`, `SystemUnit.ProductPlatform`, and `SystemUnit.Uptime`, plus the optional `BootEvent` event (`.doc/autocancellation-manifest-sample.json`)
- [ ] Automated integration tests verify message mapping, `CheckInResult` mapping (including the substring match), the no-retry rule for `Bookings.CheckIn`/`Bookings.CheckOut`, prompt-surface mapping (`RoomScheduler` excluded, sorted IDs, `403` unreadable), uptime and `BootEvent` mapping, `setMany` batching, inventory mapping, the outbound gate (including `Bookings.CheckIn.Enabled` rejected and presence writes allowed under a fleet gate), 429 backoff, and command serialization against sample Webex payload fixtures
