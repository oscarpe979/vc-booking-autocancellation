# 04: Occupancy Interruption & Automatic Check-In

**What to build:** A meeting attendee walking into a reserved room is protected from accidental release and automatically checked in. Occupancy detected before the warning (during the countdown) cancels the countdown. Occupancy detected while a warning prompt is visible keeps the prompt on screen so occupants can act on it; if the room is still occupied at expiry, the release aborts and the booking is preserved. For eligible scheduled meetings, sustained occupancy triggers one automatic check-in with tracking metadata after a brief delay. Because `Bookings.CheckedIn` is not delivered to Workspace Integrations, CheckIn confirmation comes from the service's own CheckIn result (success, or the "already checked in" error, which is how the service learns of a RoomOS native check-in), from `BookedFromDevice`, and, pending device test DT1, from a read of the booking's CheckIn state (LLD §5.9). There is no relay macro and no CheckIn command sent only to discover state.
