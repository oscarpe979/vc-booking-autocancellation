# 03: In-Room User Interaction (Audio Chimes, Prompts & Check Out)

**What to build:** An in-room meeting participant presented with an actionable warning on the touch controller can interact to preserve or immediately release their room (`LIVE` only). The warning includes dual presentation (actionable prompt on the controller, plus the OSD, which is actionable only on an interactive OSD such as Desk Pro), an audible chime at volume 70 with automatic volume restoration, a warning email to the organizer for this deadline (rules in ticket 10), and prompt text that switches from INITIAL to REPEATED after a previous Keep Booking. A Navigator controller is assumed: every prompt is sent with `Target=Controller`. Controller topology changes cannot be subscribed to, so the topology is read just in time, before and after each display and on each 60-second chime tick (LLD §5.11); there is no listener and no polling timer. If dismissed without selection, the dismissed target is restored for the remaining duration without a new email. Selecting "Keep Booking" clears the prompts and revalidates presence. Selecting "Check Out" presents a confirmation prompt, and upon positive confirmation, dispatches a user-confirmed checkout.

**Blocked by:** 02: No-Show Release Workflow & Just-In-Time Release Validation, 04: Occupancy Interruption & Automatic Check-In, 10: Corporate SMTP Email Notification Engine & Template System

- [ ] On each 60-second chime tick while a prompt is visible, `readPromptSurfaces()` runs again. If the controller-ID set changed or the read failed (including `403`), controller ownership is dropped and, when this workflow captured a set at display and a controller is now present, the current prompt is re-displayed with the remaining duration only. The deadline never moves, and no separate listener or polling timer exists
- [ ] A controller that connects mid-prompt in a room that had none at display is not given the prompt, and the booking is kept at expiry (intentional difference, LLD §5.14)
- [ ] Warning presentation routes actionable buttons (Option 1: Keep Booking, Option 2: Check Out) to `Target=Controller` and to interactive OSDs (Desk Pro), while non-interactive OSDs receive informational guidance; external room panels (`RoomScheduler`) never receive prompts and never count as a controller. A Desk Pro OSD prompt is owned through `osdPromptDisplayed` and satisfies JIT check 5 on its own
- [ ] If no actionable surface owns the prompt, the service logs it and keeps the deadline; expiry then preserves the booking (JIT check 5)

- [ ] When the warning prompt appears, the coordinator calls `playAudioAlert()` (one alert: volume 70, Announcement sound), holds 4 seconds, calls `restoreAudioVolume()`, and repeats the alert every 60 seconds while the prompt is visible; a sound failure is logged and ignored.
