# 01: Core Scaffolding & End-to-End Tracer Bullet

**What to build:** An engineer can boot a minimal local Node.js/TypeScript service that loads configuration, initializes an in-memory room registry, registers a test room, transitions the room from idle to actively tracking an eligible scheduled meeting, and cleanly shuts down. This establishes the project's foundation, defines every domain type and port contract (LLD §2), and proves the Hexagonal architecture with a passing end-to-end tracer bullet test.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] TypeScript service environment compiles cleanly and executes unit tests via a single test command
- [ ] Process configuration loads strongly typed values from environment variables and `.env.local`: Webex credentials, `ADMIN_DASHBOARD_PASSWORD`, `AUTOCANCEL_KILL_SWITCH`, and the ingress mode (`NOTIFICATION_MODE`, fixed to `longpolling`). There is no global dry-run flag: modes are per room in the roster (ticket 11)
- [ ] Runtime behaviour settings are typed as `FleetSettings` (LLD §2.2: timings, `nativeCheckInWindowMinutes`, `ultrasoundSensorEnabled`, exemptions, SMTP without credentials, `notificationsEnabled`, `earlyDepartureReleaseEnabled`, kill switch, tripwire) and are read from `IFleetConfigStore`, not from the environment. Environment / `.env.local` values for these settings only seed a brand-new store (ticket 11)
- [ ] Domain types from LLD §2.1 exist: `RoomLifecyclePhase` (`Idle`, `Quarantined`, `ActiveMeeting`, `CountdownScheduled`, `PromptPending`, `PromptVisible`, `ValidatingJIT`, `Released`), `OperatingMode` (`DISABLED`, `MONITOR_ONLY`, `DRY_RUN`, `LIVE`), exemption classifications, `CheckOutReason`, block reasons, `BookingDetails`, and `RoomAvailabilitySnapshot`
- [ ] Every port from LLD §2.2 is defined with its exact method names: `IRoomPresenceDriver`; `IRoomInteractionDriver` (`readPromptSurfaces` returning `PromptSurfaces` with `inventoryReadable`, sorted `controllerIds`, and `interactiveOsd`, never rejecting; `displayPrompt` returning `PromptDisplayResult` with `controllerCommandAccepted`; `restoreDismissedPrompt(roomId, target, prompt)`, `clearPrompts(roomId, kind)`, `playAudioAlert`, `restoreAudioVolume`, `onPromptResponse`, `onPromptCleared`); `ICalendarDriver` (`getAvailability`, `getBookingDetails`, `getCurrentBooking`, `getCheckInState` returning `BookingCheckInState | null` (marked pending device test DT1; removed if DT1 is negative), `checkIn` returning `CheckInResult`, `checkOut(roomId, bookingId, reason)`; no CheckIn event handler); `IDeviceConfigDriver` (`enforceBaselinePresenceConfig`, `getNativeCheckInEnabled`, `getNativeCheckInWindow`, `enforceNativeCheckInWindow`, `setNativeCheckInEnabled`, `getCodecTime`, `getUptimeSeconds`, `onBootEvent` with `DeviceBootEvent`); `INotificationDriver`; `IEventIngressTransport` (`start`, `stop`, `onNotification`, `onConnectivityChange`); `IFleetInventoryDriver`; and `IFleetConfigStore`
- [ ] A mock implementation of every port (including `MockFleetInventoryDriver` and an in-memory `IFleetConfigStore`) is available to the test harness
- [ ] An in-memory room registry instantiates and manages the lifecycle of room actors
- [ ] An end-to-end test passes demonstrating a room actor initializing in an idle state, receiving an active booking event, transitioning to active monitoring, and tearing down cleanly without errors
